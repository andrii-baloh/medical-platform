## 2. Главное правило общения

Каждое новое задание от ChatGPT начинается с имени исполнителя:

`DeepSeek — ЗАДАНИЕ DS-001`
`Codex — ЗАДАНИЕ CX-001`
`ZCode — ЗАДАНИЕ ZC-001`

Исполнитель отвечает в этом же файле, начиная отчёт так:

`DeepSeek — ОТЧЁТ DS-001`
`Codex — ОТЧЁТ CX-001`
`ZCode — ОТЧЁТ ZC-001`

ChatGPT завершает цикл одним из двух статусов:

`ChatGPT — ПРИНЯТО <ID>`
или
`ChatGPT — ДОРАБОТАТЬ <ID>`

Пока ChatGPT не написал «ПРИНЯТО», задача не считается завершённой.

## 5. Формат задания от ChatGPT

Каждое задание должно содержать:
- ID задачи;
- цель;
- конкретный scope;
- файлы/модули, которые можно менять;
- что нельзя менять;
- acceptance criteria;
- команды проверки;
- зависимости от других задач, если есть.
## 6. Формат отчёта исполнителя

Исполнитель обязан указать:

**Статус:** DONE / PARTIAL / BLOCKED

**Что сделано**
- конкретные изменения, без общих фраз.

**Изменённые файлы**
- полный список файлов.

**Проверки**
- команда;
- exit code;
- существенный результат.

**Ошибки / ограничения**
- всё, что не удалось проверить;
- внешние зависимости;
- runtime-проблемы.

**Риски / замечания**
- возможные race conditions, security, migration или compatibility issues.

**Git**
- commit не создавать, если он явно не был поручен;
- указать текущий diff/status, если задача затрагивала код.

## 7. Правила контроля ChatGPT

После каждого отчёта ChatGPT:
1. сам проверяет заявленные изменения;
2. смотрит `git diff` / `git status`;
3. проверяет ключевые файлы;
4. повторяет необходимые typecheck/build/tests;
5. при необходимости запускает runtime-проверку;
6. только после этого пишет «ПРИНЯТО»;
7. при ошибках создаёт точное задание на доработку.
## 8. Разделение параллельной работы

ChatGPT может назначать задачи параллельно, только если их области не конфликтуют.
Если два задания требуют изменения одного и того же файла, они выполняются последовательно,
если ChatGPT явно не определил другой порядок интеграции.

По умолчанию:
- DeepSeek может получать backend / DB / infrastructure задачи;
- Codex может получать implementation / refactor / tests / integration задачи;
- ZCode может получать frontend / UI / UX / client-integration задачи.

Это не жёсткое ограничение: конкретное назначение ChatGPT всегда важнее специализации по умолчанию.

## 9. Definition of Done

Задача считается действительно завершённой только когда:
- acceptance criteria выполнены;
- нет скрытых незавершённых пунктов;
- typecheck/tests/build прошли там, где применимо;
- migrations/configs синтаксически проверены;
- не появились новые очевидные security regressions;
- отчёт исполнителя соответствует фактическому состоянию проекта;
- ChatGPT написал «ПРИНЯТО».
